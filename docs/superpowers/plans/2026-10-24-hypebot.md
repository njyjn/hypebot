# HypeBot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Home Assistant add-on / Docker service that watches Apple Store Singapore pickup stock for chosen models and alerts via Slack, Telegram and HA notify, plus HA sensors.

**Architecture:** One Node process. `sources/` turn config into watch items and report availability; `watcher` diffs against saved state and fans out to `notifiers/` and `ha-sensors`. Config comes from `/data/options.json` or env vars.

**Tech Stack:** Node 24, TypeScript (ESM, `tsc` build), Vitest. No runtime deps.

**Spec:** `docs/superpowers/specs/2026-10-24-hypebot-design.md`

## Global Constraints

- Base image `node:24-alpine`; `engines.node: ">=24"`.
- No runtime npm dependencies (built-in `fetch`, `node:http` only in tests).
- Interval: `int(30,3600)`, default 60, plus random 0-10 s jitter per check.
- Pickup URL: `https://www.apple.com/sg/shop/retail/pickup-message?pl=true&location=238859&parts.0=...`
- Buy page URL: `https://www.apple.com/sg/shop/buy-iphone/<product>`
- Request timeout 20 s; browser-like User-Agent.
- Re-resolve catalogue every 6 h; resolution retry every 10 min while failing.
- Failure alert after 10 consecutive failed checks; one recovery note.
- State file `/data/state.json`; options file `OPTIONS_PATH` default `/data/options.json`.
- Sensor id `sensor.hypebot_<product>_<colour>_<capacity>` slugified, state `in_stock` / `out_of_stock`.
- Add-on: arch `aarch64` only, image `ghcr.io/njyjn/hypebot`, dispatch event `hypebot-released`.
- Never log secret values (tokens).

## Review Focus

- Apple returns HTML (404 / block page) instead of JSON → counts as a failed check, not a crash. Test in Task 3.
- A watched part missing from a store's `partsAvailability` → treated as unavailable. Test in Task 3.
- Same model watched twice in config (duplicate variant strings) → one watch item, one sensor. Test in Task 2.
- Restart while stock is still in stock → no repeat alert (state loaded from disk). Test in Task 4.
- Destination with only half its fields set (token but no channel) → inactive with a warning, not a failing send. Test in Task 1.

  ```ts
  export type StockState = Record<string, string[]>   // itemId -> store names in stock
  export function loadState(path: string): StockState  // {} on missing/corrupt, logs on corrupt
  export function saveState(path: string, s: StockState): void   // write tmp + rename

  }
  ```
